# Speaker Guide: Automate the Everyday with Copilot Automations

## Session overview

This session demonstrates how GitHub Copilot Automations helps teams move beyond manually prompting AI to building autonomous workflows that reduce repetitive engineering work.

**Core message:** AI has made coding faster, but the rest of the software development lifecycle hasn't kept pace. Copilot Automations helps teams automate those bottlenecks while maintaining quality and control.

### Before you present

- Review the presentation deck and watch the recorded walkthrough.
- Familiarize yourself with the three automation building blocks: **triggers, prompts, and tools**.
- Use your own existing repositories and confirm access before the day of the event.
- Have the demo links open in separate browser tabs.
- Prepare previously completed automation runs as backups.

Refer to the session transcript for additional talking points and detailed explanations if needed.

## Session flow

### 1. Setting the scene (Slides 1–15)
- AI has dramatically accelerated software development.
- Faster coding creates new bottlenecks in reviews, testing, and delivery.
- Introduce the shift from manually prompting AI to building automated engineering systems.

### 2. Introducing Copilot Automations (Slides 16–22)
- Explain the three building blocks: **triggers, prompts, and tools**.
- Highlight permissions, integrations, and cost controls.
- Emphasise that automations can run independently within defined boundaries.

### 3. Demonstrating Copilot Automations (Slides 23–26)
- Show how an automation captures screenshots and videos of UI changes in pull requests.
- Explain how this reduces manual review effort.
- Introduce how Copilot can help create automations.

### 4. Continuous improvement (Slides 27–34)
- Explain how automations use execution logs and feedback to identify improvements.
- Introduce automation groups and self-improving workflows.
- Demonstrate the improvement process using the screenshot automation.

### 5. End-to-end automation (Slides 35–38)
- Demonstrate the workflow connecting four automations:
  1. **Bug creator:** Creates an issue from a Sentry event.
  2. **Reproducer:** Reproduces the bug and captures evidence.
  3. **Fixer:** Creates a pull request with a proposed fix.
  4. **Validator:** Verifies whether the fix resolves the issue.
- Reinforce how multiple automations can work together across the SDLC.

### 6. Wrap-up (Slide 39)
- Automations move teams beyond manual prompting.
- Triggers, prompts, and tools enable flexible engineering workflows.
- Combining automations reduces toil and helps teams deliver completed software faster.
