# Demos & Donuts — Presenter Resources

## About these sessions

Demos & Donuts features short, practical **15-minute technical talks** designed to showcase GitHub capabilities through real developer workflows.

These sessions take place at the **Demos & Donuts stand** and should be engaging, informal, and demo-focused.

### Presenter guidelines

- The sessions are designed to be delivered in 15-20 minutes, allowing for Q&A to fulfill the 30 minute session.
- Prioritize demonstrations over lengthy presentations.
- Demos can and should be run live wherever possible.
- Use the presentation deck and speaker notes to guide your delivery.
- Keep explanations concise and focused on practical developer scenarios.
- Prepare a working demo environment and a backup recording or completed example.
- Encourage questions and conversations with attendees after the session.

## Sessions

### 1. Stop Waiting on Your Own Pull Requests: GitHub Stacked PRs in Practice

Learn how GitHub Stacked Pull Requests helps developers break large code changes into smaller, independently reviewable pull requests.

**Key topics:**
- Creating and managing stacked PRs with GitHub CLI and Copilot.
- Navigating, reviewing, and merging stacks.
- Managing stacked PRs in VS Code.
- Automatic merging and handling dependent changes.

**Demo focus:** Show how to create, extend, review, and merge a stack using GitHub's native tooling.

### 2. Rediscover the Command Line

Explore how GitHub Copilot CLI and traditional command-line tools work together to automate everyday development tasks.

**Key topics:**
- Comparing computer use with CLI-based automation.
- Using GitHub CLI and custom extensions.
- Building reusable workflows with `gh-notifs`.
- Customising Copilot CLI with status lines and hooks.

**Demo focus:** Demonstrate how a purpose-built CLI extension can complete repetitive tasks faster and more efficiently.

### 3. Supercharge Copilot Code Review with Custom Review Instructions

Discover how teams can teach Copilot code review their repository-specific standards, conventions, and engineering practices.

**Key topics:**
- Why repository-specific review instructions matter.
- Creating instructions in `.github/instructions/`.
- Using `applyTo` to target relevant files.
- Turning existing review feedback into reusable instructions.
- Extending review context with MCP and Copilot Memories.

**Demo focus:** Show how to add custom review instructions to a repository and use Copilot code review to identify issues based on those instructions.

**Remember:** These aren't traditional breakout sessions. The goal is to show developers something useful, demonstrate it in action, and inspire them to try it themselves.
